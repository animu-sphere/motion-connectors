# v0.2.0 — the native consumer boundary

**Tagged:** 2026-11-01 ·
[Release page](https://github.com/animu-sphere/motion-connectors/releases/tag/v0.2.0)

The release that ends acquisition at `MotionFrame` and opens the connectors to
consumers outside C++: a C ABI, a Python binding over it, a WebSocket transport
and published CLIs.

## Objective

Make the acquisition boundary something a consumer can rely on and a gate can
enforce. A connector stops at observations and `MotionFrame`, and every
downstream dependency leaves its library, package config, public headers and
manifest. A native consumer then has a stable way in, through the C ABI or an
installed package, and every library and CLI is checked as an installed package
before it is published.

## What shipped

- **Acquisition boundary**: `VmcFrameSource` and `MocopiFrameSource` end at
  acquisition, and `motionSampling` and `motionRecording` leave the VMC and mocopi
  closures. Tracker assignment owns observation identity and validates
  applicability before solve. The workspace gates refuse downstream packages and
  stage headers in workspace, standalone and installed builds
  ([DESIGN_POLICY §47](../design/DESIGN_POLICY.md#47-external-acquisition-boundary),
  [WORKSPACE §2.4](../architecture/WORKSPACE.md#24-enforcement)).
- **`motionConnectorCAbi`**: a shared library exporting only `motion_*`, over VMC,
  mocopi, VRChat OSC and WebSocket ([C_ABI.md](../design/C_ABI.md)).
- **Python binding** (`bindings/python/`): `ctypes` and the standard library over
  the C ABI, as a `py3-none-any` package
  ([DESIGN_POLICY §19.1](../design/DESIGN_POLICY.md#191-the-python-binding)).
- **`motionConnectorWire`**: the `openstrata.motion.frame/v1` codec
  ([FRAME_WIRE_FORMAT.md](../design/FRAME_WIRE_FORMAT.md)).
- **`motionConnectorWebSocket`**: `MotionFrame` over the library's own RFC 6455
  subset, in both directions and both roles
  ([WEBSOCKET_CONNECTOR.md](../design/WEBSOCKET_CONNECTOR.md)).
- **`motion_connect`**: adds `record`, `bridge` and a WebSocket source
  ([MOTION_CONNECT.md](../design/MOTION_CONNECT.md)). The recorders separate raw
  capture from trace export.
- **Acquisition references**: `motionConnectorOpenXR`,
  `web/motionConnectorWebXR` and `web/motionConnectorMediaPipe`, each caller-driven
  and producing observations.
- **`record_stream` example** (`examples/record_stream/`): connector to
  `motion-capture-trace` as a consumer program.
- **Published CLIs**: `motion_connect`, `vmc_record`, `mocopi_record` and
  `vrchat_osc_record` are artifacts under `requires.tools` pins.

The capabilities, feature by feature, are the
[capability matrix](../reference/CAPABILITY_MATRIX.md) at this tag, and the
change by change detail is the [changelog](../../CHANGELOG.md).

## Evidence

- **Installed consumers**: `ost library verify-consumer` is required for every
  published library on all three targets, and the root suite's
  `workspace_installed_consumer` consumes the installed tree outside the
  repository, including a C consumer, the Python binding and `record_stream`.
- **Replay parity**: the C ABI and the Python binding are compared with the C++
  connectors for every field, frame and diagnostic on each source's corpus.
- **Corpus replay**: every committed capture replays in CI on all three platforms.
- **Device sessions**: the recorded device sessions were not replayed for this
  release, because their bytes are not in the repository. No hardware behaviour
  is newly claimed.

## Compatibility

- **OpenUSD:** 26.08, exactly
  ([DEPENDENCIES.md §1](../architecture/DEPENDENCIES.md#1-openusd)).
- **`usd-motion-plugins`:** pinned by digest in each library's manifest
  ([DEPENDENCIES.md §2](../architecture/DEPENDENCIES.md#2-usd-motion-plugins)).
- **Platforms:** Windows x86_64, macOS arm64, Linux x86_64, each as the
  OpenStrata `cy2026` / `usd` target with Python 3.13.
- **Packages:** every library and CLI is version 0.2.0, and a consumer requires
  `>=0.2,<0.3`.
- **Breaking for a 0.1 consumer:** `motionConnectorVmc/LiveSource.h` and
  `MocopiLiveSource` leave the public API, and the VMC and mocopi packages no
  longer bring `motionSampling` or `motionRecording` with them. A consumer
  composing motion intake declares those dependencies itself.

## Known limitations at this release

- **`motionConnectorOpenXR` ships as source.** A library descriptor cannot declare
  the OpenXR loader.
- **No wheel or npm package is published.** The Python binding and the browser
  modules are in the source archive, and the browser modules keep their own npm
  version.
- **The OpenXR, WebXR and MediaPipe references have no measured hardware claim.**
  Their device observations remain [operator work](../roadmap/current.md#operator-evidence).
- **The direct tracker solve stays here** as a compatibility path, pending
  [motion-owned inputs and parity](../roadmap/boundary-implementation.md).
- **One actor per source.** `ActorId`'s type waits for the first multi-actor
  source (CC-O5).
- **No VMC sender has been recorded**, so VMC's two translation channels are
  unsettled (CS-O2).
- **The VRChat OSC tracker Euler order** is measured to three compositions of
  six, because no recorded take rolls.
- **`MOCOPI_TRACKING_LOST` is reserved and never raised.**
- **No TLS, binary encoding or several receiving peers** on WebSocket (WSC-O1,
  WSC-O2, FW-O1).
